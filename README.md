# SmileGuard 护齿管家

口腔 AI 智能筛查与健康管理系统

微信小程序 + FastAPI 后端 + YOLO 视觉检测 + 智谱 AI 文本生成与对话能力，面向居家口腔健康初筛、家庭健康管理、健康干预与科普服务场景。

## 项目概述

SmileGuard 护齿管家是一款面向普通用户的居家口腔健康 AIoT 初筛与管理平台。系统以智能手机为边缘感知节点，用户通过微信小程序拍摄牙齿图像后，后端调用 YOLO 模型完成病灶识别，再结合规则引擎输出健康评分、问题列表、风险等级和建议动作；在此基础上，智谱 AI 进一步将结构化识别结果转化为自然语言健康建议，并提供面向用户的连续问答能力。

从产品形态上看，它已经不只是“拍照识别一次”的工具，而是围绕口腔健康建立了一条完整服务链：

- AI 影像极速早筛
- 家庭健康档案管理
- 刷牙行为干预与统计
- 医疗科普内容分发
- 匿名交流社区
- AI 护齿管家对话

## 多模态系统主线

本项目的核心不是单一模型，而是多模态能力组合：

### 1. 视觉模态

由 YOLO 模型负责口腔图像中的目标检测与病灶定位，输出类别、边界框和推理结果。

### 2. 结构化模态

后端规则引擎根据识别标签计算：

- `health_score`
- `issues`
- `severity`
- `summary`
- `action`

这一步把模型输出从“框和类别”转成可被前端、数据库和后续 AI 消费的结构化健康数据。

### 3. 文本生成模态

报告页会基于识别结果调用智谱 AI 的 `glm-4-flash` 接口，把病灶结果、分数、患者身份等信息整合成更自然的中文健康建议。

### 4. 连续对话模态

聊天页对接智谱 AI 应用会话接口，支持基于检测结果继续追问，比如：

- 为什么会出现这个问题
- 日常护理怎么做
- 什么时候需要去医院
- 家长如何帮助孩子预防龋齿

所以从系统设计上看，本项目已经是“视觉识别 + 结构化报告 + 文本建议 + 连续问答”的多模态口腔健康系统。

## 核心功能

### AI 影像极速早筛

- 微信小程序调用摄像头拍照或从相册选图
- 前端进行口腔区域导引与裁剪
- 上传至 FastAPI `/predict`
- YOLO 返回检测框与类别
- 前端渲染报告页与病灶可视化框

### 结构化口腔报告

- 自动计算健康分数
- 自动汇总问题数量与问题类别
- 根据病灶类型生成风险等级
- 支持将报告绘制为海报并保存到相册

### 家庭健康档案

- 支持本人模式与家庭成员模式切换
- 基于 `patientId` 管理家庭成员历史记录
- 支持查看不同成员的趋势数据和历史报告

### 智能护齿干预

- 内置 120 秒刷牙计时器
- 以 6 阶段方式引导巴氏刷牙法
- 支持震动提醒
- 记录刷牙时长并在统计页进行趋势展示

### 医疗科普内容

- 首页提供健康 Tips
- 视频流页面提供口腔科普短视频
- 支持点赞、评论、回复等内容互动

### 匿名交流社区

- 用户可匿名发帖、评论、回复
- 支持动态时间轴与互动记录
- 面向轻量化病友交流和经验分享

### AI 护齿管家

- 基于智谱 AI 的应用接口实现连续问答
- 可将筛查分数与问题列表自动带入对话上下文
- 提供面向用户的个性化解释、建议与引导

## 多类别能力说明

### 当前数据集配置

当前 `data.yaml` 使用的是现有训练数据配置：

- `nc: 2`
- `names: ['Caries', 'Tooth']`

这说明“当前落地训练数据”主要还是龋齿与牙齿基准类。

### 当前代码中的多类别设计

但从代码层面看，系统已经明确按多类别口腔问题进行设计。`api/main.py` 中的规则引擎已经内置了多类口腔问题映射，包括：

- `CALCULUS`
- `Gingivitis`
- `Lichen`
- `caries`
- `decaycavity`
- `earlydecay`
- `healthytooth`
- `missing`
- `plaque`

这些类别在系统中的作用不仅是“预留字段”，而是已经参与：

- 中文问题名称映射
- 风险等级划分
- 健康分数扣分逻辑
- 就医/护理动作建议
- 报告页展示与海报生成

因此更准确的表述应该是：

- 当前训练数据落地版本：以 2 类为主
- 当前产品与系统设计版本：已按多类别口腔筛查平台搭建
- 当前 README 应按“多类别口腔健康平台”的方式介绍，而不是把整个项目降级为纯两分类项目

## 智谱 AI 能力说明

项目中智谱 AI 主要承担两条能力链：

### 1. 报告建议生成

报告页 `frontend/pages/report/report.js` 会将以下信息拼接为提示词：

- 患者姓名
- 患者性别
- 检测到的问题列表
- 健康分数

然后调用智谱 AI `glm-4-flash` 接口生成更自然、更像“AI 护齿管家”的口腔健康建议文本。

### 2. AI 护齿对话

聊天页 `frontend/pages/chat/chat.js` 对接智谱 AI 应用会话能力：

- 创建会话
- 生成请求 ID
- 通过 SSE 流式接收回复
- 将检测分数和问题列表作为首轮隐式上下文注入

这意味着系统不仅能“看图识别”，还能“围绕识别结果继续交流”，形成更完整的服务闭环。

## 运行与使用

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 启动后端

```bash
uvicorn api.main:app --host 0.0.0.0 --port 8000 --reload
```

可访问：

- 健康检查：`http://127.0.0.1:8000/`
- API 文档：`http://127.0.0.1:8000/docs`

### 3. 打开小程序

使用微信开发者工具打开 `frontend/` 目录。

建议重点检查：

- `frontend/project.config.json`
- `frontend/app.js`
- `frontend/pages/camera/camera.js`

## API 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 健康检查 |
| POST | `/predict` | 上传图片并返回结构化检测报告 |

返回结果核心字段：

- `health_score`
- `summary`
- `issues`
- `bboxes`
- `meta.inference_ms`
- `has_teeth`

## 局限性

- 当前训练数据配置仍以 2 类为主，多类别能力与产品设计并不完全等价于多类别模型效果
- 拍照角度、光照、清晰度会显著影响检测质量
- 早期微小病灶识别能力仍依赖后续更高质量标注数据
- 智谱 AI 生成内容属于辅助建议，不能替代医生判断
